# BACKS AIOS 0.9.7

## Build Flow keeps going across bounded episodes

A self-imposed deadline or attempt count now ends one bounded episode, not the
whole authorized mission. Build Flow checkpoints at a safe boundary, keeps the
spent counters, and continues only after a fresh episode allowance is declared.
Old usage is never reset or overwritten. The task packet gains `episode`,
`worker_state`, and an optional `continuation_binding` block.

## Native Codex Stop continuation

`hooks/codex_stop_continuation.py` is the Stop adapter. When a Codex run asks for
same-thread continuation, the task packet is bound at each durable checkpoint
with `python hooks/codex_stop_continuation.py bind-task-packet RUN_ID`. The hook
registers `Stop` and `UserPromptSubmit`, rejects a malformed continuation
identity, keeps prior episode counters, and preserves unknown rebind cost.

## Codex bundle fixes

- The Codex bundle now ships the Stop adapter. Before this release the gate
  called `hooks/codex_stop_continuation.py`, but the refresh tool never copied
  it, so a refreshed bundle could not continue.
- The bundle carries the derived `.codex-plugin/plugin.json` and no root
  `plugin.json`, which would shadow the hooks in current Codex builds.
- Referenced playbooks and the public `CLAUDE.md` travel with the bundle, so a
  copied skill resolves its method without a separate install. Compatibility
  alias folders stay out of the bundle to prevent duplicate discovery.
- Startup grounding context stays whole and bounded for Codex hosts.

## Guards

- `tests/test_public_private_union.py` stages the real pack and checks every
  hook file the gate calls, the manifest, methods, alias dedupe, Build Flow
  links, and public placeholders.
- The trailer guard now fails loud when its policy base is not in HEAD's
  history, and enforces from the last published main forward.
