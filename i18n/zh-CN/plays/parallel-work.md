# 战术：Parallel Work

如何把工作铺开给多个 agent，还不让它们互相踩踏。养活其他一切的
那条规则：一条写入主脊，多个读者。

## 什么时候用

- 任务能拆成可以同时跑的研究、扫描、测试或评审。
- 同一时间窗口里，会有不止一个 agent 碰同一个仓库。
- 你正想让两个 agent 并行写代码。先读这个。

## 链路

1. [leap-protocol](../skills/leap-protocol/SKILL.md) —— 在任何 agent 起跑
   之前，把工作拆成带目标、规格和硬性文件范围的球。
2. 派读者，不派写者——只为读多写少、交叉依赖少的工作铺开子 agent：
   研究、跑测试、安全扫描、评审。互相牵连的代码编写，绝不这样干。
3. 每条通道隔离——每个并行 agent 拿自己的 worktree（同一个仓库的独立
   检出）。这样冲突会在合并时以真正的合并冲突现身，而不是无声覆盖、
   一声不响地丢数据。
4. [clean-code-gauntlet](../skills/clean-code-gauntlet/SKILL.md) —— 每条通道
   先在自己的 worktree 里跑完自己的质量关卡，才许申请落地。先 dry-run，
   让通道知道自己的成本。任何通道都不许踩着别的通道的绿灯落地。
5. [blind-tribunal](../skills/blind-tribunal/SKILL.md) —— 评审 agent 拿一份
   干净的上下文，绝不拿作者的。共享上下文会腐坏，会自我认同。
6. 一次只合一条通道，在专用的合并工作区里，由退出码把关。

## 协同规则

- 每个工作区只有一个 agent 写代码，在一个连贯的上下文里。并行写者会
  做出彼此冲突的隐性决定，任何合并都调不回来。
- 预先声明每个 agent 的文件所有权。每个 agent 只改点名给它的文件。
- 通过跟踪器（issue、工单）协同——绝不用工作树里的共享清单文件。
  那个文件本身就是一块合并冲突面，还会让两个 agent 抢同一个任务。
- 每个子 agent 返回一份提炼过的总结——关键事实、决定、待办事项，
  一两页——绝不返回完整对话记录。
- 把计划、规格、决定持久化到磁盘，并重新读取。长跑会压缩上下文、
  悄悄丢指令；永远必须遵守的规则放在始终加载的文件里，别处都不放。

## 合并纪律

- 每一次合并落地前都由退出码把关。红色的套件拦住合并。
  光这一条，就砍掉了 agent 造成的大部分破坏。
- 在专用合并工作区里合并，然后统计核对结果：文件数、diffstat、
  每条通道点名的文件都在。悄悄丢掉某条通道文件的合并是头号恶性合并——
  每次都要查。

## 硬门槛——踩中任何一条，整场战术判负

- 两个 agent 同时在同一个工作区写代码。
- 某条通道改了它声明范围之外的文件。
- 合并落地时没有绿色退出码，或没做统计核对。
- 评审者与作者共享了上下文。
- 某条通道踩着别的通道的测试结果落地，或 mock 了它自己改动的接缝。
