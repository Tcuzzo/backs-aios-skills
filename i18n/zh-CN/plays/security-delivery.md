# 战术：Security & Delivery

任何会被客户或另一台机器运行的东西的出厂关。安全靠构造：
由 harness（约束 agent 的执行框架）强制执行，绝不指望模型记得住。

## 什么时候用

- 一个仓库、agent 或应用即将交付、发布或部署。
- 带工具的 agent 会接触不可信内容——网页、issue、邮件、外部输入。
- 你在给要交付的东西加依赖或 CI。

## 链路

1. 密钥关——用仅验证模式跑密钥扫描器（它会拿每个疑似凭据去真实服务方
   核验）。一个确认存活的凭据，就让构建失败。没有例外。
2. 出站封锁——出站默认拒绝；一切流量走一个只放行裸主机名白名单的代理。
   匹配之前先规范化并校验主机名：拒绝空字节、百分号花招和 CRLF。
   空字节绕过 `evil-host\x00.trusted.com` 是真实存在的，而且真的上过线。
3. 拆掉致命三件套（lethal trifecta）——在架构上让每条执行路径永远至少
   缺一样：私有数据访问、不可信内容接触、对外通信。你没法完全挡住
   prompt 注入；但你能让它偷不走东西。
4. 污点追踪——摄入不可信内容，就把会话标记为已污染。污染期间，
   一切能外传数据的动作（出站 HTTP、邮件、建 PR）都在 harness 里按策略
   把关——绝不交给模型自己判断。
5. 供应链——每个依赖都哈希锁定，禁掉安装期脚本。每个 CI action 都锁到
   完整 commit 哈希，不是标签。
6. [clean-code-gauntlet](../skills/clean-code-gauntlet/SKILL.md) —— 安全代码
   扛最严的标准。对每个检测器、解析器、策略谓词跑变异测试，把幸存变异体
   清到零。威胁检查里翻转了一个比较符、套件却照样通过——那本身就是漏洞。
7. [sniper-testing](../skills/sniper-testing/SKILL.md) —— 只 mock 出站网络，
   绝不 mock 被测的载荷或解析器：被 mock 掉的检测器，就是生产环境里
   瞎掉的传感器。
8. 出厂前沙箱——把构建产物放进一次性沙箱运行，出站全部封死，
   资源硬杀开关上膛。盯着它写了什么、想调用什么。
9. 溯源——产出软件物料清单（SBOM），有条件就加上签名的溯源记录。
   然后依然要审源码：溯源会把恶意源码也忠实地签下去。

## 任何构建过程中的常备保护

- 敏感路径禁写：shell 启动文件、git 配置和 hook、DNS 配置、SSH 密钥。
- 工具最小权限。确认步骤只留给真正破坏性或不可逆的操作——数据丢失、
  花钱、不可逆的对外动作。绝不拦无害能力，也绝不拦你的人。

## 硬门槛——踩中任何一条，整场战术判负

- 交付物或它的历史里，任何位置有确认存活的凭据。
- 任何一条执行路径同时握着三件套的全部三条腿。
- 未锁定的依赖、安装脚本、或锁在标签上的 CI action。
- 检测器、解析器或策略谓词里有幸存的变异体。
- 产物出厂前从没进过沙箱。
