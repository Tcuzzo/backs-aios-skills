# 编译当前请求

将操作者所说的话转成可执行契约，简短说明自己的理解，然后继续工作。
压缩表达可以包含完整规格；操作者无需把它重写成工程工单。

## 当前任务只解析一次

当前任务包已有指令，且没有新要求改变它时，复用它。本技能负责解释语言；
[operator-intent-deduction](../operator-intent-deduction/SKILL.md) 负责解决该指令
范围内的未决选择。两者都不重启对方的完整工作流。

### 1. 解析实际用词

提取所请求的能力、动作、指定界面、数量、约束和可观察的完成状态。
标记未解决的指代和比喻。重复可能表示强调，不产生第二项任务。语气可以表达
急迫，但不能确立授权、风险容忍度、能力或身份。

在实际任务背景中解释比喻。“烧掉重来”可能是在说一种方法，本身不授权删除数据。
用清晰语言回答，不模仿方言，也不编造人格。

### 2. 只查明影响行动的不确定性

在适用指令框架内按以下顺序判断：

1. 操作者当前明确的请求与纠正。
2. 本次对话已经建立的范围和授权。
3. 已验证的项目事实、目标、契约和当前状态。
4. [operator-essence](../operator-essence/SKILL.md) 中相关已确认偏好和有证据的观察。
5. 证据不足时，明确标注的暂定推断。

Essence 缺失或过时时，由其负责人执行一次受支持的洞察梳理，返回暂定或当前片段。
嵌套技能复用该结果，不重复收集历史。历史偏好不能覆盖新指令。
源码事实可以约束路径，但不能缩减目标。

定性证据说明偏好的含义与背景。定量证据可以描述其声明总体中的重复结果。
计数本身不能决定操作者的意思，报告推断的倾向也不是操作者确认过的指令。

### 3. 产出指令

将以下字段保留在现有任务包中，不另建计划：

| 字段 | 必需内容 |
| --- | --- |
| 预期能力 | 操作者想让什么存在，或想了解什么。 |
| 当前边界 | 已验证状态和可用能力今天允许做什么。 |
| 当前路径 | 在既有授权下的下一项有用行动。 |
| 后续路径 | 实现完整预期能力仍需的依赖。 |
| 任务契约 | 模式、目标、边界、要求的完成状态和验收证据。 |
| 不确定性 | 关键未知及可能解决它们的证据。 |

外部依赖限制当前路径时，仍应保留完整的预期能力。
评审产出发现，不应悄悄变成修复。

## 说明理解，然后行动

解释有必要时，用一句直白的话：

> 我的理解：更新现有集成，保留其公开接口，并在发布前验证实际消费者。

必要时标明依据薄弱的推断。继续证据支持的可逆工作。通过检查或聚焦实验解决
事实性不确定性。缺少关键授权或确有未决操作者选择时，先完成能做的准备，
再给出一项具体建议和问题；参照 [decision-bar](../decision-bar/SKILL.md)。
旧偏好不能补足新的重要行动所缺的权限。

将指令返回 [Build Flow](../backs-build-flow/SKILL.md)。只在确有剩余决定时调用
意图推导。之后的纠正更新现有任务包和相关 essence 证据，不悄悄替换目标，
也不重置剩余任务预算。
