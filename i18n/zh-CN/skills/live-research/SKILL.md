# Live Research

模型记忆只是"训练时这个项目大概长什么样"的猜测。实况真相是此刻磁盘上和官方文档里的东西。这个技能双线并行：主通道推理目标的同时，一个调研 agent 去读真东西，其发现在**任何结论落定之前**就并入推理。

## 什么时候跑

- 你正要推理一个项目的结构、一个 API 的契约、一个库的行为——而你还没读过当前源码。
- 某个设计、修复或论断依赖的事实，可能在你的训练数据之后已经变了。
- 一个问题需要现有上下文答不了的真实世界事实。

## 步骤

1. **并行拉起调研者。** 对某个目标的推理一启动，就同时派一个后台调研 agent 扑向同一目标。主通道继续干活；调研者去读。agent 自己能干的跑腿活，绝不拿来阻塞主线。
2. **读实况真相，由近及远。** 先项目自己的 README，再离目标最近的分区文档，然后真正的源码结构——真实的目录列表、真实的文件内容、真实的函数签名。项目之外的事实：官方文档、源码、规范、第一方 API。一篇复述文档的博客不是一手来源。
3. **结论之前，先把发现流回来。** 发现一落地就流向主通道，推理随之吸收并修正航向。调研者还没就某一点回报，就先下的结论只是猜测——标注成猜测，直到实况真相证实或击杀它。
4. **每条论断钉在拥有它的来源上。** 每个发现内联携带来源：一个文件路径、一行引文、一个链接、一个 commit。钉不住来源的论断就大声标成未验证——绝不打扮成事实。
5. **写一份带引用的文件。** 所有发现落进单个 Markdown 文件，每条论断带来源。存到项目已有的笔记惯例位置；没有惯例就挑个合理的地方并说明在哪，让下一个 agent 找得到。
6. **重读之前先回忆。** 先查早前会话的笔记——同一来源可能已经拉取过。复用缓存的发现，引用同一来源。几分钟的回忆胜过几小时的重新发掘。

## 硬性规则

- **合并之前没有结论。** 调研者尚未就某一点回报，主通道就不得把那一点当定论说出口。
- **只认一手来源。** 每条论断都追溯到拥有它的来源。二手转述只是指针，不是证明。
- **无头模式，绝不占用有人看着的浏览器。** 后台调研走无头抓取路径——绝不用人正在看的实况浏览器；那是另一条通道。
- **验证不了就明说。** 没有一手来源的发现要打上旗子发出，绝不悄悄混进其余内容。
- **对人零摩擦。** 这个技能不加审批步骤、不设关卡。它是方法纪律，不是检查站。

## 会得到什么

一份有据可查、带引用的 Markdown 文件——外加一条在飞行途中就被纠偏、而不是等结论发出后才补救的推理通道。主通道读完文件，继续前进。
