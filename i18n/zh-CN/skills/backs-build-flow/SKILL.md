# BACKS Build Flow

由一位集成负责人将请求从上下文整理推进到经验证的交付。
专业技能向这位负责人返回证据，不重新启动工作流。
对于无需构建或调查的简单回答，仅使用相关步骤。

## 建立足够行动的上下文

1. 保留用户的目标、约束、既有授权和要求的结果。选择模式：**build/fix**、
   **read-only review**、**investigate** 或 **resume/deliver**。
   评审本身不授权编辑、安装或部署。
2. 复用当前任务包。若没有，使用 [context-engineer](../context-engineer/SKILL.md)
   验证目标、适用指令、受影响的调用方与消费路径、已有工作和验收检查。
   [building-with-backs](../building-with-backs/SKILL.md) 负责确定工作副本和晋级路径。
   固定改动前的 `base_sha`；随着工作提交，更新 `candidate_sha`。
3. 针对当前操作者应用 [operator-essence](../operator-essence/SKILL.md)：
   载入相关的认知片段，或在档案缺失时执行一次洞察引导。
   定性观察和定量证据用于指导沟通与验证；它们不授予权限，也不固化人格。
   证据不足时标记为暂定，并继续有用且已获授权的工作。
   仅在意图模糊时使用 [intent-compiler](../intent-compiler/SKILL.md)；
   [operator-intent-deduction](../operator-intent-deduction/SKILL.md) 负责判断
   重要的未决选择是否确实需要操作者决定。
4. **能说清目标、下一项具体行动、约束以及可观察的验收检查时，就开始执行。**
   继续阅读必须是为了解决一个可能改变该行动的明确问题，不要反复绘制整个仓库地图。

## 每项技能只路由一次，明确输出和退出条件

载入实际相关的技能正文；名字或回执本身不算应用。复用上下文中仍然存在且有效的
正文和证据。压缩上下文后，只重载下一步所需的内容。对每个专业技能说明目的、
预期证据和退出条件；按需阅读更深入的参考资料。用一份当前任务包记录负责人、
状态和下一步（[任务包与交接格式](references/task-packet.md)），不要另建重复账本。

采用外部能力时，[absorb](../absorb/SKILL.md) 负责能力映射和原生集成。
[rea-investigation](../rea-investigation/SKILL.md) 在需要时提供发现或验证证据，
然后返回调用方，不递归启动 Absorb。普通源码工作直接使用源码和测试。

## 执行有界的 RED → GREEN 循环

重试前绑定 [bounded-loops](../bounded-loops/SKILL.md)：一个 `mission_id`、
截止时间、尝试/轮次额度以及剩余资源预算。子工作者、模型切换、修复发现和
评审轮次都消耗同一额度。

1. **RED：** [red-first](../red-first/SKILL.md) 在修复前建立真实失败的行为检查。
   保留其封存文件和基线身份。评审或研究任务使用其证据契约，不人为制造编辑。
2. **构建：** 在负责该行为的接缝上实现最小而完整的改动，更新受影响的消费者和
   兼容接口，保留无关工作。
3. **Lint 与测试：** [sniper-testing](../sniper-testing/SKILL.md) 从 `base_sha`
   到当前候选版本推导范围，包括相关待提交工作。执行仓库适用的 lint、格式检查、
   类型检查和行为测试。记录确切命令、版本、结果及不可用或不适用的检查。
   工作区干净不会抹去已经提交的任务范围。
4. **质量：** [clean-code-gauntlet](../clean-code-gauntlet/SKILL.md) 在相同范围和
   预算内执行质量度量、有界隔离变异测试和独立评审。新缺口另加补充测试，
   不重写已封存的 RED。
5. **响应证据：** 修复已证实的发现，仅重跑受影响的检查。相同失败反复出现时，
   必须改变假设或方法。额度耗尽则为未完成工作建立检查点；绝不重置预算或降低检查标准。

候选版本稳定后，执行仓库要求的汇总落地关卡。如实报告当前宿主具备的能力，
不要编造工具、测试或评审。

## 完成用户要求的结果

请求包含打包、提交、发布和验证时，继续完成其中已获授权的步骤。确实需要外部
批准时，先准备完整且可审阅的结果。按用户希望的节奏说明发现、当前行动、证据
以及查看实时工作的位置。

区分**请求的任务已交付**和不变量底线中的 **PROVEN** 能力状态。
完成本地补丁或只读评审不代表已经线上部署。必需关卡失败或不可用时应明确保留：
以 **STILL-BUILDING** 建立检查点，写清阻碍、剩余额度和下一步。
只读模式下，在回复或已获授权的外部任务记录中返回任务包；不要隐式创建仓库账本
或 essence 文件。
