# Red-First, Tamper-Proof
**Effort:** free — 纯顺序纪律：你反正要写的测试先写、先证明是红的、再用一次 commit 封存；防篡改检查就是一条 git diff。消除：照着修复长出来只为能过的测试，以及构建者靠改测试掰弯的绿色裁决。

仅在修复后观察到绿色结果，既不能证明原始失败，也不能证明测试能检测到它。
修复前先证明并封存原始 RED；构建者须保持该文件不变。后续可在独立的补充
回归测试中，证明相关受控变异体会失败、未变异候选会通过，具体流程见下文。

使用当前 [BACKS Build Flow](../backs-build-flow/SKILL.md) 任务包。本技能负责 RED
封存，不另建构建负责人或生命周期。保留固定的 `base_sha`、当前 `candidate_sha`
和任务身份。[bounded-loops](../bounded-loops/SKILL.md) 的截止时间与剩余尝试数
同时约束复现、构建者、补充测试和独立评审。复用有效的已有 RED 回执，不制造新失败。

## 什么时候跑

派出任何构建或修复之前——只要想要的行为能用一条测试说清。这是 bug 修复和新能力共同的默认。

## 步骤

1. **写那条失败的契约测试。** 用能捕捉"该行为缺失"的最小形式，写出你想要的行为。它现在必须是失败的。
2. **证明它是红的。** 跑这条测试，亲眼看它失败——而且是因为对的理由。import 就报错的测试、悄悄通过的测试，都不算红。没人跑过的红测试是猜测，不是基线。
3. **派发构建者前先提交 RED。** 记录提交 ID、确切测试路径与字节、失败命令/输出
   及原因。此提交是红色基线和防篡改封条，不替换用于汇总改动范围的任务 `base_sha`。
4. **给构建者只派一个活：让它变绿。** 构建者禁止碰测试文件。派活时明说。
5. **独立评分。** 一位没写这次改动的评分者查两件事：
   - 测试现在通过；
   - 测试文件与红色基线逐字节一致——
     `git diff <red-sha> <candidate_sha> -- tests/test_contract.py` 输出为空。
     检查包含待提交工作时，还须比较实际受测文件字节与封条；干净的提交差异
     不能为已暂存或未暂存编辑开脱。
   测试文件上有任何 diff 都判评分失败。没有例外，"只是修了个错别字"也不行。
6. **一个结构性守卫，胜过散落的点测试。** 结构性守卫是一种能拦住"下一个"违规者的检查（grep 扫描、AST 扫描、lint 规则），不是只钉住这一例。一个守卫顶十个各钉一例的点测试。

## 原始封存后出现新发现

幸存变异体或评审发现可能暴露缺失断言。保持原始 RED 文件逐字节一致，另加
**独立的补充测试文件**。新缺陷修复前观察该测试失败；变异缺口则在隔离的相关
受控变异体上证明失败，并在未变异候选上通过。下一位构建者改变接缝前，记录并
封存补充证据。不要声称这是最初基线。评分者检查两份封条和确切汇总候选版本。
添加测试绝不授权弱化、重命名或替换原始契约。

共享预算耗尽或无法建立 RED 时，以 **STILL-BUILDING** 建立检查点，说明缺口和
准确下一步。不编造 RED，也不为强求绿色而重置任务。

## 硬性规则

- **红必须被证明是红。** 跑它、看它失败，才算数。
- **构建者从不编辑测试。** 自红色基线以来测试文件 diff 为空，是落地关卡的一部分，不是顺手一查。
- **构建者绝不当评分者。** 用一个非构建者出身的评分者，按能力与可用性从
  配置好的梯级矩阵里在线挑出；构建候选的作者执行被取消资格，任何继承了构建
  者对话或上下文的会话同样被取消资格；评审者必须使用全新且与作者无关的会话。
- **只有绿不算证明。** 绿 + 原封测试 + 独立评分证明此契约；声称线上能力仍需
  任务工作流要求的真实界面和交付证据。
- **牵涉一整类缺陷时，守住这一类。** 点测试挡得住这个 bug；结构性守卫挡得住下一个。

## 搭配使用

- [sniper-testing](../sniper-testing/SKILL.md) — 迭代时只跑改动触及的测试；落地时一次全量。
- [seam-engineering](../seam-engineering/SKILL.md) — 结构性守卫所属的"修一类"纪律。
- [blind-tribunal](../blind-tribunal/SKILL.md) — 从没见过作者的独立评分者。
- [repair-loop](../repair-loop/SKILL.md) — 把红 → 绿 → 已证明端到端跑完的循环。
