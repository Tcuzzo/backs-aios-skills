# Know Your Human——了解你的人类
**Effort:** light — 一轮画像：加载已存的人物画像，或用至多 7 个闲聊式问题建一份。消除：反复审问一个早已回答过的人，以及误读其品味的构建带来的返工。

一次误读了服务对象的构建，第一行代码还没写就已经错了。这个技能用一份可用的人物模型取代猜测：思维模式、品味、语气偏好、以及在哪些领域他的话可以直接信。到人所在的地方去见他——绝不逼人升到系统的层面。

## 什么时候跑

任何构建、设计、升级或有分量的 UX 决策开始时。不是聊天点缀。

## 流程：有画像就加载，没有就问

1. **认出这个人。** 先查项目里的 `.agent/profiles/<human>.md`，再查 agent 的家目录
   配置（如 `~/.claude/profiles/<human>.md`）里的跨项目画像。有已验证的画像就加载并
   应用。已有画像的人绝不重新盘问。
2. **没有画像？走问题协议**（见下）。至多 7 个轻松的问题，外加至多 3 个在回答打开了
   话头时的追问。永远可选——不想答的人就改从观察到的行为建档。绝不拿它卡住工作。
3. **合成一份会话画像**（模板见下）。每个字段都带 `source` 和 `status`。没有证据的
   部分留空：留空是诚实，猜测是一条藏起来的推断。
4. **对齐目标。** 用这份画像、用这个人自己的语气，把构建意图复述一遍——一段大白话，
   不是规格书。他确认或纠正。他的纠正是终审。
5. **给自己重写提示。** 执行之前，把你的工作 prompt 透过画像改写一遍：他到底想说
   什么、哪些话直接信、哪些需要一次不动声色的确认、什么会让他觉得带劲、什么会让他
   觉得被冒犯。
6. **让画像当整个构建的引导之手**——设计、工程、UX、品味决策全部顺着它走。
7. **持续学习。** 观察到的选择、拒绝和纠正随时更新画像——存回
   `.agent/profiles/<human>.md`（跨项目画像存家目录配置）。纠正即时生效，永远赢。

## 接地阶梯（优先级，绝对）

```
人类的纠正（HUMAN CORRECTION）
  > 观察到的重复行为（OBSERVED REPEATED BEHAVIOR）
  > 自述的原型（DECLARED ARCHETYPE——他说自己是什么样的人）
  > 文化模式（CULTURAL PATTERN——那个原型通常意味着什么）
  > 模型猜测（MODEL GUESS）
```

低层永远压不过高层。原型和文化模式只是引导的语境，绝不是套人的盒子——观察到的行为和纠正压过它们。

## 问题协议

设计规则：不需要任何学历就能回答。轻松的判断题和二选一。一次一个，撒在目标对话里——绝不连珠炮、绝不打分、绝不重复。记下人自己的原话；措辞和答案一样重要。

7 个核心问题（每个同时读出两条以上的轴）：
1. 新买的电子产品：先看说明书，还是拿起来就按？→ 加工风格、风险偏好。
2. 判断题：丑陋的 bug 比慢更折磨你。→ 品味优先级（审美 vs 机械）。
3. 朋友迟到了：发条短信，还是打个电话听完整来龙去脉？→ 语气偏好（压缩 vs 叙事）。
4. 搭一个树屋：先想象成品，还是先想第一块板子？→ 全局思维 vs 步骤思维。
5. 判断题：讲不通的规则也应该遵守。→ 接受框架 vs 挑战框架。
6. 三个不错的选项，还是一个你可以否决的强烈推荐？
   → 权威偏好——直接决定你怎么呈现决策。
7. 他的作品被批评了：辩护、动手改、还是反问"你会怎么做"？
   → 纠正风格——决定你怎么递交扎手的发现。

追问（至多 3 个，只在核心回答打开话头时）：直觉是处处可信，还是只在擅长的领域可信（信任地图）；"够好就行"行不行（发布偏好）；以后能改的自由 vs 今天就能用的确定（可逆性品味）；别人改过之后还算不算他的（所有权）；"别人对你的工作方式最大的误解是什么？"（身份锚点，用他的原话）。

## 信任规则

画像标出这个人的判断力强在哪、弱在哪。
- **强项 + 说得笃定 → 直接信。** 不重新推导、不反复怀疑、不把基础知识讲回给人听。
- **弱项 + 说得含糊 → 一次不动声色的确认。** 问一个轻松的问题化解歧义，或给出你的
  理解让他一个词确认。绝不当面反驳；也绝不悄悄换成你自己的方案。
- **绝不拿画像限制这个人可以尝试什么。** 它调的是你怎么听，绝不是你听不听。

## 会话画像模板（紧凑版）

```markdown
# SESSION PROFILE —— <human>
## 身份锚点        # 取值 + 来源（declared|observed|cultural|guess）+ 状态（confirmed|working|needs-validation|rejected）
## 工作模式        # 一段话：这些锚点在这个人身上如何组合
## 引导特征        # "他多半会：<行为>" → "所以我：<具体的 agent 规则>"
## 信任地图        # 强项（直接信）/ 弱项（一次不动声色的确认）
## 核心张力        # 看似矛盾、实为并存的需求
## 误读风险        # 最可能的误读，写成一条禁止句
## 台账            # 日期、阶梯层级、变更、证据
```

会话画像只在本会话内有效：到了新会话它是数据，不是真相，直到人重新确认或行为重新验证。画像是这个人的财产：他要看就给看、他说错了就当场改、绝不基于一条他看不见的推断行动——那是一道藏起来的门。

## 硬规则（踩中任何一条即失败）

- 重新盘问一个已有已验证画像的人。
- 让问题像考试，或把它变成必答。
- 把猜出来的字段打扮成确认过的。
- 让阶梯的低层压过高层。
- 用画像限制这个人被允许尝试什么。
- 因为一条路走不通就调低目标。要拆开说：想要的能力 → 当前边界 → 现在可走的路 →
  以后要修的路。
