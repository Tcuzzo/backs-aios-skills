# 精准测试

通过真实消费者验证改变的行为。用完整任务差异选择检查，再只重跑下一次改动
影响的检查。继承 [bounded-loops](../bounded-loops/SKILL.md) 的同一任务额度。

## 1. 固定真实范围

在 [Build Flow](../backs-build-flow/SKILL.md) 任务包中保留已验证的任务前
`base_sha` 和当前已提交的 `candidate_sha`。提交 RED 和修复后，工作区即使干净，
任务差异仍然存在。仅用 `git diff HEAD` 会丢掉它。

从本技能解析出的目录运行随附的只读范围辅助工具：

```bash
python scripts/changed_files.py --repo <verified-repo> --base <base-sha> --candidate <candidate-sha>
```

迭代时，仅当候选版本为 HEAD 才添加 `--include-worktree`。它分别报告已提交、
已暂存、未暂存和未跟踪路径，并保留特殊文件名。汇总范围包含删除和重命名两端。
将无关待提交工作标为保留，不把所有返回路径都认作自己的。缺失基线或无效版本
是需要解决的错误，不能当成空范围来跳过检查。辅助工具不拉取或改写历史。

## 2. 选择并执行真实检查

将改动文件及受影响的调用方/消费者映射到行为测试，再阅读仓库实际的脚本、CI
和配置，确定适用命令。

| 检查 | 范围与证据 |
| --- | --- |
| Lint 和格式检查 | 用已有配置检查受支持的改动文件；决定重排格式前先用检查模式。 |
| 类型检查或编译器 | 受影响的包/项目边界；类型依赖可能要求更广的目标。 |
| 行为测试 | 实际变动路径，以及能力损坏时会失败的回归测试。 |
| 契约/集成测试 | 本次改动触及的消费者、别名、打包、设置保留或运行时边界。 |
| 必需落地关卡 | 候选版本稳定后，执行仓库规定的测试集。 |

说明每条命令、覆盖何种风险、版本/待提交状态、实际结果和剩余失败。
缺少 linter 或类型检查器时，标为**不可用**或**不适用**并给出理由，不编造通过。
不要只因示例提到某工具就安装它。Lint 通过不能替代行为测试。

迭代时选最小而有意义的目标。被执行代码、输入或相关环境未变时，已经通过的
检查无需重跑。具体的未决耦合或项目必需关卡可以支持扩大测试范围，应记录理由。
落地时，对最终候选版本执行一次必需汇总检查。之后的改动只使受影响的证据和
必需提交关卡失效。

## 3. 让测试发现真实损坏

断言可观察结果：产物存在且有效、真实本地数据库能读回数据、宿主收到实际
上下文字节，或 UI 元素确实渲染。实际使用本地文件、数据库和 socket，不模拟它们。
按量计费的外部传输末端可替换为确定性 fixture，但请求构造、路由、解析和本地
消费者必须真实。绝不声称 fixture 证明了外部服务运行。

保持 [red-first](../red-first/SKILL.md) 封存的 RED 文件逐字节一致。新缺口出现时，
按该技能的证据与封存规则添加独立的补充回归测试文件。绝不弱化、重命名、
替换或编辑原始封存文件。

## 退出

向同一负责人返回候选范围、已执行的 lint/类型/测试结果、真实副作用证据和
未解决关卡。[clean-code-gauntlet](../clean-code-gauntlet/SKILL.md) 将这些作为
第一阶段证据，不把它当成重复未变检查的理由。
