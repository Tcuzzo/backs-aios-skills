# Fleet Ladder——模型阶梯
**Effort:** light — 任何派发之前，对目标梯级做一次带缓存的实况探测。消除：把活派给已死的服务商，以及写死在调用点、模型退役当天就断掉的模型名。

本技能说明选择方法，本身不解析模型。公开包不提供解析器或 Fleet 可执行程序；运行时缺少所需功能时应明确报告缺口。不要在技能、提示词或调用点硬编码模型 ID。

## 什么时候跑

- 任何派给模型的工作之前：构建、评审、review、有界工人任务。
- 服务商挂了、你需要知道谁回退到谁的时候。
- 你发现自己正往代码或 prompt 模板里敲模型名的那一刻。

## 步骤

1. **声明角色和所需能力。** 读取已配置阶梯及其顺序，按任务、能力和可用性选择合适候选。示例配置只是模板；本技能不对候选排序或过滤。
2. **验证独立性。** 评审必须在与作者分离的新执行中，使用去除作者上下文的冻结材料。通过配置的阶梯选择有能力的评审者；额外限制应作为运行时缺口报告。
任何具备相应能力的评审者都可以在与作者分离的新会话中进行评审；模型和提供商身份不构成限制。
3. **验证真实推理。** 模型列表不能证明推理、能力或配额。对候选执行真实、有界的推理请求；合理缓存结果并遵守退避。回退时重新验证能力。
4. **大声往下走。** 派给最好的可用梯级。传输失败时，大声报告失败，再试下一级。
   绝不无声跳过——记录必须能看出哪些梯级失败了、为什么。
5. **耗尽就大声失败。** 每一级都挂了，就抛一个写明试过什么的清晰错误。派不出去的
   任务绝不无声成功、无限等待、或降级成一个编造的答案。
6. **记录来源。** 每次派单都追加日志：角色、选中的模型、跳过的梯级及原因。事后你必须
   答得出"这活到底是谁干的？"

## 硬规则——破一条即失败

- 不要在技能、提示词或调用点硬编码模型 ID；使用实际配置中的角色和所需能力。
- 必须进行真实、有界的推理探测，单独的目录列表不够。
- 评审需要与作者分离的新执行和去除作者上下文的冻结材料。
- 记录失败与回退；缺少解析器或隔离机制时应报告运行时缺口。
