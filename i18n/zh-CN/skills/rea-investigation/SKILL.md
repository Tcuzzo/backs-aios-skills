# REA 产物调查

调查已发布二进制、软件包或所请求的运行时行为时，使用已安装的 REA 引擎及其
对应的独立技能。普通源码仓库直接用源码和测试。本桥接不安装 REA、Ghidra、
提供方或 MCP 服务，也不声称它们可用。

使用调用方的 [BACKS Build Flow](../backs-build-flow/SKILL.md) 任务包、集成负责人
和允许的 `task_mode`。直接调查时仅建立一次任务包。
[bounded-loops](../bounded-loops/SKILL.md) 负责截止时间和剩余额度；提供方重试、
模型切换和交接都继承它们。本技能产出证据，不成为第二个采用或修复负责人。

1. 确定确切目标、身份/哈希、问题和阶段：上游产物的**发现**，或特定原生结果的
   **验证**。从宿主的智能体技能目录读取已安装的上游 `reverse-engineer-anything`
   技能及相关参考资料，避免递归选中本桥接。若不可用，如实说明，并用现有工具
   在既有预算内继续有用的调查。
2. 有连接的 REA 工具时使用它们，否则使用已安装的 REA CLI。原生二进制分析在
   受支持时使用现有兼容的 Ghidra 提供方；缺失或不可用应报告，不编造结果，
   也不在未获授权时安装依赖。
3. 从只读静态检查开始。记录目标身份、证据 ID、范围、限制和未知项。静态发现
   不证明运行时行为；只在用户要求的范围及工具声明的执行/修改边界内进行实时观察。
4. 向调用方返回证据包：目标身份、阶段、命令/工具回执、证据 ID、观察、静态与
   运行时区别、未知项和剩余任务预算。下一步由调用方负责：Absorb 执行其许可/
   依赖关卡和原生集成；修复负责人应用 root-cause-first 和 repair-loop。
   不从本桥接递归开启任何一个生命周期。验证发现缺陷时，返回观察供封存 RED
   和有界修复/检查循环使用，不声称修复已经完成。
5. 通过配置的 fleet-ladder 按角色和能力确定派发，不硬编码模型标识。
   需要独立评估时，使用 blind-tribunal 的全新、与作者隔离的执行和隐去作者的
   任务包，并以宿主运行时实际具备的能力为限。提供方缺失或预算耗尽时，建立
   **STILL-BUILDING** 检查点，保留有用观察和准确下一步，绝不能编造运行时证明。
   未受阻调查仍须在剩余额度内。

脚手架：morluto 的 REA，MIT 许可证，https://github.com/morluto/rea。
引擎、上游技能和提供方需分别安装。
