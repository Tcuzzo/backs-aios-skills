# 使用 REA 调查制品

对已发布的二进制文件、软件包或请求调查的运行时行为，使用已安装的 REA 引擎及其独立技能。普通源代码仓库直接使用源码和测试。本桥接技能不安装 REA、Ghidra、提供程序或 MCP 服务器，也不声称它们可用。

1. 确定准确目标和问题。读取主机代理技能目录中已安装的原始 REA 技能及其相关资料，避免递归选择本桥接技能。如不可用，明确说明并用现有工具继续有效调查。
2. 优先使用可用的已连接 REA 工具，或使用已安装的 REA CLI。分析受支持的原生二进制文件时使用现有兼容的 Ghidra 提供程序；缺失或不可用时应报告，不得编造结果或未经授权安装依赖。
3. 从只读静态检查开始，记录目标身份、证据标识、范围、限制和未知事项。静态发现不能证明运行时行为；仅在用户请求范围以及工具声明的执行和修改边界内进行实时观察。
4. 将发现交给 root-cause-first 和 repair-loop。采用开源能力时调用 absorb 并检查许可证和依赖。通过已配置的 fleet-ladder 按角色和能力选择，不得硬编码模型 ID。独立评估使用 blind-tribunal 中与作者分离的新执行及去除作者信息的冻结材料，实际能力以主机运行时为准。
