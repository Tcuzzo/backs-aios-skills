# Absorb——收编前人成果，别重复造轮子
**Effort:** light — 一次仓库收编（元数据探测 + 浅 clone），外加对移植成果的一次独立评审。消除：重新发明前人早已解决的能力——那个从零造出来、每个 bug 都得你自己背的复制品。

**能力才是王道。** 仓库只是能力的载体。当你需要的东西已经有现成项目做到了，不要从零造一个复制品，也不要 clone 过来直接粘贴。找到最好的前人成果，把能力抽出来，按你自己的 harness（运行框架）改造重写，并注明脚手架出处。引用是事实陈述，不是装饰。

## 什么时候用

- 有人让你加一个能力（工具、技能、agent、流水线），而开源界大概率已经解决过。
- 你正准备 `git clone` 然后原样复制代码——停，改走这条路。
- 只是一段代码片段、一个配置值、一次查资料？跳过本技能，直接读就行。

## 步骤

使用当前 [BACKS Build Flow](../backs-build-flow/SKILL.md) 任务包和集成负责人。
直接调用时只建立一次任务包；嵌套调用将采用证据返回调用方。复用有效上下文、
operator essence 和已载入技能正文。[bounded-loops](../bounded-loops/SKILL.md)
负责任务截止时间及剩余尝试/轮次额度；发现、构建、变异、评审、模型切换和交接
都消耗同一预算。新阶段或工作者不重置它。遵守 `task_mode`：评审或诊断不授权
原生编辑或交付。

1. **先找前人成果。** 动手前先搜索。自己发明的复制品比收编来的脚手架更糟：你继承不到任何实战检验，还得独自背下所有 bug。
2. **发现 README 之外的内容。** 从平台 API 取得项目元数据（许可、活跃度、语言），
   浅克隆到临时目录，阅读代码和测试。对源码检查无法回答的已发布产物或所请求
   运行时行为，以确切目标和有界问题调用
   [rea-investigation](../rea-investigation/SKILL.md)。REA 向本调用方返回证据，
   不重启 Absorb。决定采用内容前记录上游身份、观察、限制和未知项。
   静态发现不能确立运行时行为。
3. **过信任关卡。**
   - *License：*宽松协议（MIT / Apache / BSD / MPL）= 可以放心改造。
     Copyleft（GPL / AGPL）= 只学思路——改造它的想法，绝不复制它的代码。
     没有 license = 按"保留所有权利"对待，只学思路。
     含非商用条款 = 硬阻塞，找你的人类拍板。
   - *可疑扫描：*用 `rg` 排查 cloak / spam / 刷好评 / 诈骗类模式。发现就大声标出。
   - *不装野依赖：*绝不 `pip install` / `npm install` 未经审查的依赖（typo-squatting
     拼写仿冒是真实存在的供应链攻击）。改成在你自己的原语之上写一层薄代码。
   - *能力是真的吗？*用独立证据核实宣传。卖家的博客是主张，不是证据。结论四选一：
     真实 / 吹嘘 / 骗局 / 无法核实。
   - *出口受控：*改造后版本的一切外部请求都必须限流、缓存、可随时叫停。
4. **拆解成能力地图。** 项目提供的每一项能力都记下：做什么、怎么做、承重的接缝在哪、
   哪些是臃肿或风险、你自己的栈里有什么可复用、最终是原生落地还是套一层薄适配器。
   每一项能力都要**保留，或拿出证据否决**。悄悄丢掉一项能力就是缺陷。
5. **写改造规格。** 要搭的接缝、要砍的臃肿（大声记录，绝不悄悄删），以及每项能力一条
   会失败的契约测试——断言真实的副作用：一个文件、一行数据库记录、一份真实输出。
   只允许 mock 付费外部 API 的传输层，逻辑绝不 mock。
6. **原生集成。** 应用 [red-first](../red-first/SKILL.md)：在负责行为的接缝上做
   最小修复前，观察真实失败并封存契约。原始测试文件保持不变。
   用 [sniper-testing](../sniper-testing/SKILL.md) 根据固定的 `base_sha`、当前
   `candidate_sha` 以及适用的自有待提交路径，确定仓库实际 lint、类型检查和
   测试命令的范围。明确记录不可用或不适用检查，不任意安装检查器或编造通过。
   在当前流程中运行 [clean-code-gauntlet](../clean-code-gauntlet/SKILL.md)
   获取质量与变异证据。测试缺口另加补充回归文件，不编辑封存原件。所有工作
   均在共享预算内。
7. **验证采用后的能力。** 对照能力地图并在用户实际界面上运行原生结果。
   复用发现证据；只为明确未解决的比较请求进一步 REA 观察，并遵守既有提供方
   与执行边界。从配置梯级矩阵选择有能力的评分者，在全新、与作者隔离的会话中
   评审确切汇总候选版本；记录并排除作者执行。构建者永不自评。执行必需的受影响
   测试集落地检查，遵循项目已授权交付流程。上游静态证据或本地 GREEN 单独都
   不能证明原生线上交付。
8. **注明出处并记录。** 在能力所在处记录作者、项目、许可、借用的脚手架和自己的
   改造内容。不编造或删除致谢。向集成负责人返回能力地图、确切候选版本、检查结果、
   出处和未决缺口。预算耗尽或必需关卡无法运行时，以 **STILL-BUILDING** 建立
   检查点，说明剩余工作和下一步；可继续不消耗已尽额度的有用已授权工作。
   不编造 **PROVEN**，也不为了通过而悄悄丢弃能力。

## 硬规则——踩中任何一条即失败

- 原样复制代码，而不是改造能力本身。
- 从没搜过前人成果就造复制品。
- 信 README 或营销页面，不信代码。
- 装野依赖，而不是改造它的技术思路。
- 复制 copyleft 或无 license 的代码（永远只学思路）。
- 丢掉一项能力却没写下书面否决。
- 能力测试搞 mock 剧场——测试必须触碰真实副作用。
- 没写脚手架致谢就发布。

## 搭配使用

- [red-first](../red-first/SKILL.md)——守护每项能力的契约测试。
- [sniper-testing](../sniper-testing/SKILL.md)——真实副作用，不搞 mock 剧场。
- [blind-tribunal](../blind-tribunal/SKILL.md)——对这次移植做独立评审。
- [decision-bar](../decision-bar/SKILL.md)——license 阻塞和品味判断找你的人类，其余一律执行。
