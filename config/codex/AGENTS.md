## BACKS AIOS operating instructions

At the start of each Codex task, load the installed `optimus` and `invariant-floor` skills before changing code. Read actual bodies from the active BACKS AIOS plugin or managed skill directory. Apply `backs-build-flow` as the single task coordinator: reuse the current packet, act when the target, constraints, next action and acceptance check are known, and select specialists for a defined output and exit. Actual bodies still present in context can be reused; a remembered summary is not a body. Match `repo-map`, `root-cause-first`, `repair-loop`, `red-first`, `sniper-testing`, `clean-code-gauntlet` and `secure-delivery` to the current task.

Keep bounded RED/GREEN work, repository lint/type/behavior checks, quality review and delivery inside the same mission allowance. Preserve the pre-task base and current candidate revisions so committed changes remain in test scope. Worker changes, review findings and handoffs do not reset the budget. REA returns evidence to its caller; Absorb owns native adoption. Keep task mode and established authorization explicit.

Use `operator-essence` for the current operator's relevant private awareness slice. If missing or stale, perform its one supported insights assessment or supplied-evidence fallback, then continue with current or provisional context. `human-calibration` reuses that same evidence pass. Qualitative observations and quantitative counts retain their sources, denominators, uncertainty and counterexamples; no profile overrides the current request or grants authority. Show material progress and an inspectable task record when appropriate.

For ambiguous language, use `intent-compiler` once. Use `operator-intent-deduction` for a real unresolved choice before asking the operator, and `context-engineer` for missing task context. Preserve the latest correction over generic process. Keep changes in the intended repository and verify the real path before claiming completion. Never report that a skill or hook ran when only its metadata was discovered. A missing or failed hook is a visible diagnostic, never a reason to hide failure or block tools.

When BACKS AIOS files have been refreshed, start a new Codex task to load the new skill list. A running task retains the skill context it already received. The local plugin's lifecycle hooks require Codex's explicit trust review; if not trusted or unavailable, use the installed skills and explicitly load `optimus` with `node "$HOME/.local/share/backs-aios/current/hooks/aios_gate.js" --load backs-aios:optimus`. Surface a loader failure instead of pretending it ran.
